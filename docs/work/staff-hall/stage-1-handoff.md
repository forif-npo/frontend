- dev OpenAPI 확인일: 2026-10-11

## 기존 구현 중 재사용 요청

1. 회원은 기존 `tb_user` ID로 연결한다.
2. 운영진 후보는 `tb_forif_team`의 활동 학기와 `tb_staff_account`의 ADMIN 계정 존재를 교차 확인한다.
3. 모집·열람자 변경은 기존 `requirePresidentTeam`, 필요한 경우 `requirePresident`를 재사용한다.
4. 회차·전시 시즌은 기존 학기 조회 계약을 참고하되 과거 기록을 현재 학기 변경에 종속시키지 않는다.
5. 운영진 모집 기간은 기존 스터디 `SemesterPhase`와 분리하고 미설정 시 차단한다.
6. 운영진 지원서는 `tb_user_apply`를 전용하지 않는다.
7. 전시 이미지는 공개 파일 저장을 사용할 수 있으나 지원서 첨부를 채택하면 공개 `/files/**`와 분리한다.

## 프론트에서 필요한 최소 계약

### 2단계 선행

- 공개 현재 모집 조회: 안내 필드, 부서, 문항, 서버 계산 `application_open`과 차단 사유
- 회장단 모집 CRUD: draft/published/closed/canceled 상태와 유효한 전이
- 시작·마감은 offset 포함 ISO 8601, Asia/Seoul의 정확한 포함/제외 경계
- 공개 회차가 없을 때 200+null인지 404인지 명시
- 활성 회차 중복, 잘못된 기간, 권한 없음의 오류 코드

### 3단계 선행

- 본인 제출·조회와 관리자 목록·상세
- 사용자 확정 정책은 로그인한 정회원, 한 회차당 1회 제출, 1지망·2지망 허용
- 동일 회차+사용자 중복 제출의 DB 제약과 409
- 기존 회원 데이터에서 정회원을 판정하는 정확한 조건
- 1·2지망 저장·중복 부서 차단·2지망 필수 여부, 문항 snapshot·개인정보 반환 범위
- 목록과 상세의 페이지네이션·검색·필터
- 로그인/세션 만료와 제출 중 재시도 시 중복 생성 방지
- 지원서 개인정보 snapshot·답변·지망은 DB에 영구 보관. 기간 기반 자동 삭제 작업은
  구현하지 않고 접근·감사·backup 보호를 계약에 명시

### 4단계 선행

- 기존 ADMIN 중 활동 학기 후보 조회
- 회차+대상 계정 유일성
- 즉시 권한 부여, 만료·회수와 다음 조회부터 즉시 403
- 지원자와 reviewer 중복의 이해충돌 처리
- reviewer가 모집 수정·다른 reviewer 초대·다른 회차 조회를 못 하는 서비스 검사

### 5~6단계 선행

- 전시 draft CRUD, 이미지, 순서, 미리보기, 게시·게시 중단
- 공개 목록·상세는 published만 반환
- 시즌 filter·정렬·slug·사진 없음·긴 텍스트 계약
- 편집 권한을 회장단으로 제한할지 일반 ADMIN까지 허용할지 확정

## 경로·필드 주의

- `contract.md`의 API 경로는 frontend 후보이며 확정하지 않았다.
- backend body는 기존 규칙대로 snake_case를 유지해 달라.
- dev OpenAPI 출력은 일부 camelCase로 보이므로 Jackson/OpenAPI 표시와 실제 JSON을 함께 검증해 달라.
- `application_open`은 client 계산이 아니라 server 판정을 요청한다.
- 목록에는 최소 개인정보만, 전체 답변·연락처는 권한이 검증된 상세에만 반환해 달라.
- 개인정보 응답은 public cache에 남지 않도록 cache header를 계약에 포함해 달라.

## 확정된 정책과 남은 결정

사용자가 확정한 정책:

- 로그인한 정회원만 지원 가능
- 한 회차당 1회 제출, 1지망·2지망 허용
- 개인정보 snapshot·답변·지망은 DB에 영구 보관하고 자동 삭제하지 않음

다음 항목은 backend가 임의 확정하지 말고 회장단 결정을 받아야 한다.

- 제출 후 수정·취소·재지원
- 임시저장·첨부파일
- 정회원 판정 기준, 2지망 필수 여부
- 향후 삭제 요구가 생길 경우 별도 삭제 권한·감사·backup 처리 범위
- reviewer 지원 이해충돌
- 명예의 전당 편집 권한과 선정·철회 정책

프론트 권장안은 임시저장·첨부·수정·취소를 1차 범위에서 제외하고, 기존 ADMIN에게 회차별
열람 권한을 즉시 부여하며, 명예의 전당은 수동 등록·게시로 시작하는 것이다. 이는 승인된
정책이 아니다.
