# PR·코드 리뷰 컨벤션

## PR 작성자

PR은 하나의 검토 가능한 목적을 가져야 합니다. 너무 큰 변경은 기능 단위나 준비 PR로
나누고, 다른 사람의 변경을 함께 정리하지 않습니다.

PR 본문에는 아래를 반드시 적습니다.

- 변경한 앱·패키지와 변경 목적
- 사용자 동작, API 계약, 권한, 화면 출력에 미치는 영향
- 실행한 검증 명령과 수동 확인 방법
- UI 변경의 전후 화면 또는 확인한 viewport
- 남은 위험, 후속 작업, 아직 결정되지 않은 사항

환경 변수, 권한, 인증, API 형식, URL, 배포 설정을 바꾼 경우에는 영향 범위와 롤백 방법을
특히 명확히 작성합니다.

## 리뷰어

리뷰는 코드 스타일보다 제품 계약과 회귀 위험을 먼저 봅니다.

- 요구 사항과 사용자 흐름이 충족되는지 확인합니다.
- 권한, 데이터 형식, 오류·빈 상태, 접근성, 반응형을 확인합니다.
- 변경 범위에 맞는 테스트와 검증 증거가 있는지 확인합니다.
- 차단해야 하는 문제와 제안 사항을 구분해 전달합니다.

작성자는 모든 피드백을 반영하거나, 반영하지 않는 이유를 답변합니다. 승인 뒤 의미 있는
변경이 추가되면 필요한 리뷰를 다시 요청합니다.
