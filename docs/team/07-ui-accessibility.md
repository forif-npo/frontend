# UI·접근성 컨벤션

## 공통 기준

- 기존 component variant와 semantic token을 우선 사용합니다.
- 색상만으로 상태·중요도를 전달하지 않고 텍스트, 아이콘, 형태 등 보조 단서를 제공합니다.
- 모든 입력에는 연결된 label을 제공하고, 버튼·대화상자·목록은 의미에 맞는 HTML과 role을 사용합니다.
- 키보드로 조작할 수 있어야 하며 focus 상태가 명확히 보여야 합니다.
- loading, empty, error, disabled 상태에서도 현재 맥락과 다음 행동을 알 수 있어야 합니다.

## 반응형 확인

UI 변경은 최소한 아래 viewport에서 확인합니다.

| 구간    | viewport   | 중점 확인                                 |
| ------- | ---------- | ----------------------------------------- |
| mobile  | 390 × 844  | 터치, 줄바꿈, form·table·메뉴의 대체 표현 |
| tablet  | 768 × 1024 | 전환 직후의 grid, navigation, 행동 영역   |
| desktop | 1440 × 900 | 최대 폭, 여백, 긴 콘텐츠, 병렬 정보       |

핵심 행동과 오류·필수 입력은 mobile에서 숨기지 않습니다. 가로 스크롤은 표·캘린더처럼 열
비교가 본질인 경우에만 사용하고, 스크롤 가능성·키보드 접근을 함께 제공합니다.
