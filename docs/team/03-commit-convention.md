# 커밋 컨벤션

커밋 하나는 리뷰와 되돌리기가 가능한 하나의 의도를 담습니다. 기능 변경, 리팩터링,
포맷 전용 변경을 불필요하게 섞지 않습니다.

## 메시지 형식

커밋 메시지는 변경 의도를 짧고 구체적으로 씁니다. 필요하면 저장소 루트에서
`pnpm commit`으로 대화형 도우미를 사용할 수 있습니다.

```text
<type>(<scope>): <변경 의도>
```

| type       | 사용 시점                 |
| ---------- | ------------------------- |
| `feat`     | 사용자 기능 추가          |
| `fix`      | 결함 수정                 |
| `refactor` | 동작을 보존하는 구조 개선 |
| `test`     | 테스트 추가·수정          |
| `docs`     | 문서 변경                 |
| `chore`    | 도구·설정·유지보수        |

예: `feat(study): 신청 가능 인원 표시`, `fix(auth): 만료 세션의 로그인 이동 처리`

## 기준

- 제목만으로 무엇이 바뀌었는지 이해할 수 있게 작성합니다.
- 관련 없는 변경은 별도 커밋으로 나눕니다.
- 생성물, 개인 IDE 설정, 비밀 값은 커밋하지 않습니다.
- 리팩터링이 사용자 동작이나 API 계약을 바꾸면 `refactor`로 숨기지 않고 영향과 검증을 PR에 명시합니다.
