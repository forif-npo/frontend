# 테스트 컨벤션

테스트는 구현 세부 사항보다 사용자 동작과 데이터 경계의 계약을 검증합니다. 테스트 대상은
변경의 위험도와 사용자 영향으로 결정합니다.

## 최소 확인

| 변경                        | 최소 확인                            |
| --------------------------- | ------------------------------------ |
| 순수 함수·schema·변환       | 단위 테스트                          |
| form·dialog·filter·mutation | 사용자 상호작용 중심 컴포넌트 테스트 |
| API 어댑터·응답 처리        | 요청·응답·오류 경계 테스트           |
| UI 변경                     | 자동 테스트와 browser 수동 확인      |
| 공통 설정·배포 설정         | 관련 workspace 확인과 `pnpm build`   |

fixture는 실제 API 계약에 가까운 최소 데이터를 사용합니다. mock은 네트워크, 시간, browser
API처럼 테스트 경계를 넘는 의존성에 한정하고, 도메인 로직 자체를 과도하게 mock하지 않습니다.
fixture와 mock에는 실제 개인정보(이름, 학번, 연락처, 이메일, 주소 등)를 절대 넣지 않고,
식별할 수 없는 가상 값만 사용합니다. 실제 형식 검증이 필요해도 실제 사용자 정보와 무관한
예약·예시 값을 사용합니다.

병합 전에는 `pnpm lint`, `pnpm type-check`, `pnpm test`를 실행합니다.
